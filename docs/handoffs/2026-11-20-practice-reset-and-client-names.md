# 단말 이름과 관제 연습 초기화 인수 — 2026-11-20

## 변경 결과

- 시험 단말 컨테이너 `client-A`(172.28.10.11), 대조 `client-B`(172.28.10.12). Compose 서비스 이름과 IP는 유지. browser 연결·기존 일차별 시험 스크립트의 컨테이너 참조 갱신. 선택 multi-ip 단말은 변경하지 않음.
- 기본 비활성의 담당자용 관제 기록 초기화 버튼. 기존 ERP loopback 입구가 서버 측 인증·CSRF·출처를 검사하며, 활성/대기/불확실 승인이나 실제 차단 규칙이 있으면 거부.
- 원본 파일·ERP DB·코드·기존 백업·공식 증거·게이트웨이 승인/감사 기록은 유지. 수집기가 배치 사이에 대기하고 같은 Python/DB 연결에서 관제 기록 삭제·파일 inode/EOF checkpoint를 함께 저장. 부분 줄은 완성돼도 이전 기록으로 건너뜀.
- 웹·ERP·수집기 컨테이너를 초기화 클릭마다 재시작하지 않음. Python 새 실행도 초기화 경로에서 제거. 화면은 진행·실패·실제 처리 시간을 표시.

## 검증

- `PYTHONPATH=src python -m unittest discover -s tests`: 48건 중47통과, PostgreSQL 연결 환경변수 없는 연동 시험1건 건너뜀. 코드 자체를 PostgreSQL 전체 상시 운영 통과로 보고하지 않음.
- `node --test testbed/browser/practice-reset.test.cjs`: 6건 통과. 가짜 Docker 경로로 인증/CSRF·활성 승인 거부·실패·컨테이너/파일 불변 동작 확인.
- 원본 보존·이전 로그 재수집 방지·새 live 유지·부분 줄·checkpoint 저장 실패 rollback·수집기 요청 실행은 SQLite 시험 포함.
- A PC 별도 PostgreSQL 시험 DB(합성 행1개)에서 실제 초기화: HTTP200, 3.534초, 시험 raw0건. 시험 worker는 미리 준비한 상태이며 실제 상시 수집기도 실행 상태를 재사용. 원래 관제 DB 보존, 원본 파일 유지, 시험 DB/worker 정리 완료. 현재 관제 DB를 자동 삭제한 시험과 구분.
- 이전 느린 경로의 읽기 전용 단계 실측: Python 시작1.945초 +3.813초 + 모듈 로딩12.109초. 새 경로에서는 이 세 실행을 제거.
- 실제 loopback 대시보드/ERP HTTP200, 미인증 초기화403 확인. 새 코드의 로그인→차단→해제 전체 E2E는 별도 재실행하지 않음.

## 다른 PC에서 이어가기

최신 main을 고정 브랜치에 merge하고 Docker/로컬 비밀값을 해당 PC에서 준비한다. 원본/관제 데이터나 비밀값은 Git으로 옮기지 않는다. [연습 모드 활성화](../../testbed/browser/README.md)대로 수집기와 대시보드를 함께 build하고 브라우저 입구를 실행한다. 공식 증거가 섞인 DB에서는 초기화를 켜지 않는다.

## 공유 영향

A: 컨테이너 이름 호출 갱신. B: 수집 대기/요청 프로토콜, 부분 줄 경계, 버튼/조치 유예 반영. 기존 로그 이벤트 필드와 게이트웨이 조치 API 계약은 유지한다. 로컬 지침·원본 로그·백업은 이 인수 문서에 포함하지 않는다.
