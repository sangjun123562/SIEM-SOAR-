# 심야·휴일 로그인 시도

- 정책 파일: `src/soc/access_time_policy.json`. 변경 후 수집기·대시보드 재빌드 필요.
- KST 평일 07:00 이상 23:00 미만은 시간상 정상 범위. 23:00~07:00은 심야.
- 토·일 및 `holidays`에 등록한 `YYYY-MM-DD`는 휴일. 법정 공휴일 자동 연동은 하지 않는다.
- 대상은 ERP의 `login_success`, `login_failed`, `login_source_denied`, `login_blocked`이다.
- Gateway 차단 패킷을 로그인 시도로 추정하지 않는다. ERP 로그가 없으면 로그인 시도 횟수에 포함하지 않는다.
- 단독 시간 조건은 사건·차단을 생성하지 않는다. 기존 탐지 결과의 ID, 실패 횟수, 자동 계정 잠금, IP 수동 승인 자격은 유지한다.
- 기존 사건에 심야·휴일 실시간·신뢰 로그인 근거가 있으면 동일 심각도 내에서 우선 표시한다. 조사·합성 기록은 우선순위를 높이지 않는다.
- 신규 정규화 이벤트의 `details.access_time`에 정책 버전·해시, KST 시각, 당시 시간 기준, 심야·휴일 여부, 예외 승인 근거를 저장한다. 입력 로그가 보낸 예외 표시는 신뢰하지 않는다.
- 과거에 수집한 이벤트는 화면에서 현재 정책으로 재평가하며, 수집 당시 판정으로 소급 저장하지 않는다. 툴팁·사건 근거에 재평가 여부를 구분한다.
- 예외 항목에는 `username`, `starts_at`, `ends_at`, `approved_by`, `reason`이 모두 필요하다. 시각은 시간대가 명시된 ISO 8601이며 시작 포함·종료 미포함이다. 계정 전체에 대한 무기한 예외는 지원하지 않는다.
- 그래프 음영은 심야 구간만 표시하며 주말·공휴일의 낮은 칠하지 않는다. 운영 화면의 기존 전역 테마 토큰을 사용한다.

## 검증

`tests/test_access_time.py`: 07시·23시 경계, 주말·등록 휴무일, 계정별 승인 예외 및 만료, 모든 로그인 결과, 입력 예외 위조 무시, 단독 시간 조건의 사건 미생성, 기존 3회·5회·실패 후 성공 규칙의 ID·실패 수·차단 자격 불변, 조사·합성 기록 우선순위 억제, 심야 그래프 영역을 확인한다.
