# 보고서 AI 초안

핵심 판단 입력칸 옆의 `AI 초안` 버튼이 집계 숫자를 바탕으로 결론 초안을 만들어 입력칸에 채운다.
저장과 확정은 사람이 한다. 기본은 켜져 있지만, 키가 없으면 버튼이 보이지 않는다(끄려면 `SOC_AI_ENABLED=0`).

## 켜는 법
`.env`(Git에 올라가지 않는다)에 아래를 넣고 관제 컨테이너를 다시 올린다.

```
SOC_AI_ENABLED=1                # 생략해도 켜짐
SOC_AI_API_KEY=<OpenAI 프로젝트에서 발급한 키>
SOC_AI_MODEL=gpt-4o-mini        # 프로젝트가 쓸 수 있는 모델로 바꾼다
```

```
docker compose -f docker-compose.soc.yml --profile live up -d --build
```

OpenAI 프로젝트의 사용 한도·결제 설정과 모델 접근 권한이 없으면 호출이 거부된다(화면에 사유가 한 줄로 뜬다).

## 밖으로 나가는 것 (가장 보수적으로)
- **숫자와 고정 용어만** 나간다: 건수, 비율, 경과일, 심각도·상태 라벨, 기간 날짜.
- **사건 제목, IP, 계정명, 경로, 로그 문장은 아예 보내지 않는다.** 그래서 로그에 지시문을 심어 AI를 속이는
  공격(프롬프트 주입)이 들어갈 길이 없다.
- 보내기 직전에 서버가 한 번 더 검사한다(`assert_safe_facts`). 숫자·고정 어휘·날짜 꼴이 아닌 값이 하나라도 있으면 호출하지 않는다.
- 화면의 `보내는 내용 미리 보기`로 실제 전송 내용을 그대로 볼 수 있다(외부 호출 없음).
- OpenAI 호출은 `store=false`, 사용자 식별자 없음, 리다이렉트 차단, TLS 검증, `api.openai.com` 고정.

## 받은 글을 믿지 않는다
- 글 속 숫자가 보낸 사실에 없으면 1회 재시도 후 폐기한다.
- 링크, 이메일, IP 주소, 태그, 코드블록이 있거나 700자를 넘으면 폐기한다.
- 결과는 제안 카드에만 글자로 나오고, 사람이 `바꾸기/덧붙이기/버리기`를 고른 뒤 직접 저장한다. AI는 어떤 동작도 실행하지 못한다.

## 한도와 기록
- 사용자당 분당 3회, 서버 전체 하루 `SOC_AI_DAILY_LIMIT`회(기본 50).
- 쓰기 권한이 있는 사람만 쓴다(버튼도 안 보인다).
- 서버 로그(`soc.ai`)에는 누가·언제·어느 보고서·결과 코드(ok/rejected/rate_limited/daily_cap)만 남긴다. 보낸 내용과 받은 글은 남기지 않는다.
- AI 초안을 쓴 보고서에는 `ai.summary` 표시가 저장되고, 확정하면 함께 고정된다. 읽는 화면에도 안내가 뜬다.

## 운영 전 확인할 것
- 조직의 외부 서비스 전송 정책과 개인정보 정책에서 집계 숫자 전송이 허용되는지.
- OpenAI 프로젝트의 월 사용 한도, 키 권한(Restricted), 데이터 보관·학습 사용 설정.
- 외부 전송이 불가능하면 `SOC_AI_ENABLED=0` 으로 끈다(버튼이 사라진다).

## 코드
- `src/soc/ai_draft.py`: 사실 만들기, 가림과 복원, 숫자 검증, 호출(외부 호출은 `call_api` 한 곳).
- `POST /reports/ai-draft`: `src/soc/dashboard.py`.
- 지원하는 칸은 지금 `summary`(핵심 판단)뿐이다. 칸을 늘리려면 `FIELD_TASKS`에 문구를 더한다.
