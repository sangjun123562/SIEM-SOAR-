## 설계 원칙 (바꾸지 말 것)

협의로 확정된 것들이다. 이유가 있으니 모르고 되돌리지 말 것.

1. **차트 계열색에 빨강·노랑을 쓰지 않는다.** `dashboard.py`의 테마 주석이
   "빨강·주황·노랑은 상태 전용"이라고 이미 예약했다. 계열은 무채색 농도 + 사선(`--hatch`).
   `--danger`/`--warn`은 선·띠·점으로만, 면 채움 금지.
2. **색·아이콘만으로 의미를 전달하지 않는다.** 흑백 인쇄와 색각 이상에서 죽는다.
3. **호버 전용 정보 금지.** `title` 속성으로만 주는 설명도 금지(터치·키보드·인쇄에서 안 보임).
4. **모든 수치에서 2클릭 내 원본 로그·사건으로.** 드릴다운 없는 지표는 넣지 않는다.
5. **사람 필수 입력은 `핵심 판단`(키는 `summary`)이고, 그 글이 보고서 첫 줄로 렌더된다.**
   필수는 '근거'가 아니라 '결론'이다. 비면 확정 불가(기존 검증 그대로 동작).
6. **기계 문장과 사람 입력은 영역을 가른다.** 기계는 `--sunken` 배경 + 좌측 띠 + "편집할 수 없습니다".
7. **옛 확정본 호환**: 스냅샷의 새 키는 전부 `.get()`으로 방어. 없으면 "저장되어 있지 않습니다"로 표기.
8. 새 색 토큰을 만들지 않는다. 전역 테마 토큰만 쓴다. px 단위(rem 금지).

## 남은 일 (우선순위 순)

### 1·2. (완료) 인쇄 글자 대비 / 수집 공백 화면
원인: 다크 기본 테마의 밝은 `--text-*`가 인쇄에 그대로 쓰임 → `@media print`에서 `.rp-view` 토큰을 라이트 값으로 재정의함.
`snapshot["ingest"]` 구조와 '`None`을 공백으로 칠하지 않는다' 규칙은 아래 코드 주석으로 옮길 때까지 유지:
`snapshot["ingest"]` 구조:
```python
{
  "bucket_hours": 1,                       # weekly=1, monthly=6 (표시 칸 크기)
  "period_start_kst": "...", "period_end_kst": "...",   # 끝은 미포함
  "period_open": True,                     # 집계 시각에 기간이 안 끝났는가
  "observed_to_kst": "...",                # 여기까지만 평가(덜 찬 현재 시간 제외)
  "min_gap_hours": 3, "sparse_active_ratio": 0.25,
  "sources": [  # 순서 고정: erp, gateway, caddy, waf
    {"key": "erp", "label": "ERP", "total": 12043,
     "buckets": [12, 0, None, ...],        # 0=평가했고 0건 / None=평가 안 함
     "max_gap_hours": 6,                   # no_data면 None
     "gap_start_kst": ..., "gap_end_kst": ..., "gap_ongoing": False,
     "state": "ok" | "gap" | "sparse" | "no_data",
     "observed_from_kst": ..., "had_prior_data": True,
     "evaluated_hours": 168, "active_hours": 150},
  ]
}
```
**화면이 반드시 지킬 것**: `None`을 공백으로 칠하면 안 된다(수집 시작 전·미래 시각·덜 찬 칸).
`0`만 공백이다. 0건 칸은 **사선 패턴**으로(색만으로는 흑백 인쇄 불가).
`no_data`는 "전 구간 공백"이 아니라 "트래픽이 없던 것인지 수집이 끊긴 것인지 구분 불가"로 적는다.

### 3. (구현 완료, B 협의·화면 확인 남음) 2차 — 후속 조치 장부화

원래 요구:
자유 서술 `followup` 2000자를 **구조화 목록**으로 바꾼다. 보고서가 "매주 새로 쓰는 글"에서
"이어지는 관리"가 되는 핵심이다.
- 새 테이블 `report_followups` (`weekly_reports`처럼 `CREATE TABLE IF NOT EXISTS`로 자체 생성)

  → 한 행에 `[확정 당시] → [현재]` **2열을 나란히**. 확정본에서도 상태 변경 폼만 살린다.
