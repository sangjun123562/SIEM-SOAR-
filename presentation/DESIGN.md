## 시각 방향

**Editorial Infographic × Security Engineering × Product Showcase.** 미니멀 디자인은 우선순위를 설계하는 일이다. 한 장에서 핵심 요소를 더 크게, 흐름을 더 뚜렷하게, 정보 간 대비를 더 명확하게 만든다. 나머지 요소는 핵심을 읽거나 증거를 검토하는 데 필요한 만큼 배치한다. 적은 요소로도 화면의 밀도와 균형을 만들어야 한다.

- 사용자 레퍼런스의 저채도 세이지·올리브, 베이지, 웜 그레이, 흑백과 밝고 어두운 장의 리듬을 따른다. 시작점은 세이지 `#7C8572`, 올리브 `#5A6350`, 샌드 `#E8E5D9`, 오프화이트 `#F8F7F1`, 먹색 `#25261F`, 제품 차콜 `#22262C`다. 역할이 분명할 때만 출처색과 차단·복구 상태색을 쓴다.
- 영문 제목과 수치는 편집 디자인의 세리프 인상을 살린다. 한글 제목은 발표 거리에서 또렷한 한글 서체를 사용한다. 본문 20–24pt, 도식 16–20pt, 출처 12–14pt를 출발점으로 하며, 글자를 줄이기 전에 정보 배열을 고친다.
- 원형·반원·곡선·계층형 그래픽은 경계, 집합, 분기, 상태 변화처럼 설명할 관계가 있을 때 쓴다. 비율과 수량을 뜻하는 도형은 확인된 값에만 비례시킨다. 화면 전체에 동일한 카드, 헤더, 구분선을 반복하지 않는다.

## 05 아키텍처 · 영역부터 읽히게

- **상단 시험망, 하단 SOC, 좌하단 공유 로그, 하단 별도 조치 API 밴드**를 기본으로 한다. 각 영역은 간결한 제목·톤·여백을 갖춘 작업 공간처럼 보이게 한다. Node.js 브라우저 중계는 시험망 바깥, 공유 볼륨은 수집 경계에 둔다. 영역과 서비스에 같은 시각 기호를 쓰지 않는다.
- **업무 통신**은 회색 중간 굵기 실선, 전진 화살표. **로그 수집**은 파란 점선, 파일이 합류하는 방향과 읽기 전용 표기. **보안 조치**는 진한 청록색 굵은 실선, Gateway와 ERP까지 닿는 두 화살표. 색·형태·굵기·방향 모두에서 구별한다. 범례는 읽는 법을 요약한다. 본문에서도 차이가 바로 보여야 한다.
- **Gateway·Collector·Dashboard**는 각각 통신 제어, 수집, 사람 조치의 중심점이다. 진한 제목, 포인트 라벨, 더 강한 외곽선 또는 밝은 프레임 중 필요한 조합을 공통 적용한다. 보조 모듈은 단순한 이름·라벨로 낮추고 두 DB와 공유 볼륨은 저장소 형태로 표현한다.
- 동일 크기의 박스를 가로로 반복하지 않는다. 연결선이 실제 노드에 닿게 하고, 글자를 가로지르지 않도록 바깥 경로나 독립 밴드를 활용한다. Mermaid는 논리 검토용으로 사용 가능하다. 제출하는 PPT의 핵심 도형과 선은 편집할 수 있어야 한다.

## 07 제품 쇼케이스 · 선택한 근거가 보여야 함

- **왼쪽 전체 Sentinel 화면을 본문 시각 영역의 약 55–65%**로 배치한다. 우측 위에는 실제 선택 단계, 우측 아래에는 같은 사건의 상세 로그를 놓는다. 원본 화면의 역할은 위치 맥락이고 확대의 역할은 발표 거리에서 증거를 읽는 것이다.
- 선택한 행에 얇은 강조 프레임을 붙이고 확대까지 연결선 하나로 연결한다. 실제 UI의 비율과 문구를 보존한다. 읽기 어려우면 해상도를 높이거나 확대할 범위를 좁힌다. 캡처 내 강조는 1–3개면 충분하다.
- 캡션은 핵심 판단을 전달한다. 예를 들어 화면 근거가 확인되면 **“동일 IP에서 여러 계정 실패”**, **“신뢰 IP · 실시간 수집”**을 대비와 글자 크기로 강조한다. “원본 근거까지 추적”은 실제 원본 연결을 확인한 경우에만 쓴다. 화면 캡션과 동일 내용의 설명문을 반복하지 않는다.

## 10 검증 · 숫자와 상태의 위계를 분리

- 제목은 **“대상 단말만 차단했고, 해제 후 접속이 복구됐습니다”**처럼 실제 확인한 변화로 쓴다. 화면의 가장 큰 요소는 **시험 단말 A와 대조 단말 B의 동기화된 두 줄 시간축**이다.
- 차단 전/중/해제 후를 같은 눈금에 두고 정상은 중립색, 접속 불가는 경고색과 사각 마커, 복구는 청록과 원형 마커 등으로 표현한다. 각 상태에 짧은 태그와 문구를 병기한다. 차단 중 대조 B가 정상이라는 점을 같은 열에서 바로 읽을 수 있어야 한다.
- 옆이나 아래에 **3회 / 20개 / 0건**을 각각 **숫자·라벨·한 줄 맥락**이 있는 데이터 블록으로 둔다. 예시는 “3회 / 반복 / 동일 시나리오”, “20개 / 회차당 / 검증 점검”, “0건 / 실패 / 해당 세 회차”다. 세 숫자는 같은 크기 장식 카드로 화면을 지배하지 않게 한다. 실질적인 상태 변화보다 먼저 읽히지 않도록 비중을 제한한다.
- 안전장치는 2–3개의 짧은 묶음이나 얇은 밴드로 연결한다. 날짜·환경·시험 커밋·자동화 범위를 캡션으로 명시하고 상세 조건은 노트와 부록에 둔다.

## 검수 기준

각 장을 실제 렌더 이미지와 축소판에서 확인한다. 3초 안에 장의 역할이 읽히는가, 핵심 도형이 정보에 기여하는가, 본문 경로와 근거가 정확한가, 발표장에서 증거·상태 태그·한글을 충분히 읽을 수 있는가를 점검한다. 구조도는 세 경로를 각각 따라가고, 제품은 원본→확대를 대조하며, 검증은 A/B의 전후 차이와 시험 범위를 확인한다. 어느 장도 기본 사각형만 반복하거나 권한·시험·제품 데이터를 가정해 채우지 않는다.
