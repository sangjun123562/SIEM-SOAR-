점검일 2026-11-18 / A 고정 브랜치 eldi.

이는 최초 계획의 구매 업무 요구를 축소한 변경이다. 과거 DB 데이터·관제 증거는 보존한다.

## 판정

**A의 변경된 4일 차 범위는 검증 완료. 4일 차 전체 운영 통합은 아직 완료가 아니다.**

## 실행한 시험

- python -B -m unittest discover -s tests -v: 22개 중 21 통과, PostgreSQL 실제 통합 1개 건너뜀.
- bash testbed/scripts/verify_day4.sh: 실제 요청 17건, pass=19 fail=0, 종료 0.
  UTC 02:32:52~02:33:55. 정상 로그인1, 실패8(신뢰7/미신뢰1), 로그아웃1.
- 제거한 4개 경로와 동작의 404, 직접 ERP 접속 정책 차단, 실패5건의 request_id 정확 연결 확인.
- 실제 생성 파일을 읽는 정규화는 collection_mode=replay다. 이 사건을 실제 차단 근거로 쓰지 않고 조치 API는 연결하지 않았다.
- 원본 식별에 사용하는 offset은 UTF-8 파일의 실제 바이트 위치로 계산한다.
- verify_network_layout.py: 네트워크 소속·internal·포트 비공개·권한·자원·경로 통과.
- 일반 Chrome/localhost: 구매 메뉴와 입력형 필드 없음, 계정 선택·실패/정상 로그인·세션 확인·로그아웃 검증. 전용 프록시/인증서 예외 없이 동작.
- 소스/환경 예시의 비밀값·로컬 전용 파일 포함 여부를 PR 게시 전 별도로 점검한다.

## 유지한 범위와 B 인수인계

- login_success/login_failed/logout 필드와 기존 raw_id 계약은 유지한다.
- 기존 purchase_* 로그 유형은 과거 증거 해석을 위해 계약에서 지우지 않는다. 새로운 업무 이벤트는 생성하지 않는다.
- ERP DB 테이블/행 및 모든 로그·CA 볼륨을 초기화하지 않는다.
- 사람의 방화벽 차단 승인은 유지 대상이다. 제거한 것은 ERP 내부의 구매 결재다.
- 일반 브라우저 연결 도구와 재현 방법은 [browser/README.md](browser/README.md).
- B의 운영 통합에는 검증된 생성기 볼륨을 읽는 수집 경로의 live 설정, 관제 DB에서 사건을 읽는 연결과 지속 갱신이 필요하다.
- 실제 조치 연동 전 담당자 인증·승인 요청 출처 검증·승인 이력 보존도 확인해야 한다. 화면의 승인자 문자열은 인증 자체가 아니다.
- 파일 재처리/단위 시험을 실제 라이브 수집 또는 전체 시연 성공으로 보고하지 않는다.
