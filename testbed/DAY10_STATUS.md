# 10일 차 점검 — A PC 핵심 시연 3회 연속 검증

점검일: 2026-11-20(KST) / 담당: A 검증 / 시험 버전: eldi `abb755f`.
문서 게시 전 최신 main을 merge했으며, 이 표의 실행 결과는 merge 이전 시험 버전 기준이다.

## 판정

**기존 핵심 흐름의 3회 연속 실제 통합 시험 통과. 10일 차 전체 인수는 진행 중.**
ERP 로그인 실패 → live 수집 → 사건 → 인증 담당자 승인 경로 → 시험 단말만 차단 → 해제·복구를 검증했다.
승인 경로는 시험 스크립트가 인증된 담당자로 호출했다. 사람이 화면에서 직접 클릭하는 발표 리허설과 구분한다.

## 실행 환경·안전 확인

- 기존 격리 Docker Linux 시험망(A PC), Docker Engine 29.9.1 / Compose 5.6.0.
- 기존 A·B live 컨테이너를 `up -d --no-build --pull never`로 시작. 다운로드·볼륨 초기화·기존 관제 증거 삭제 없음.
- 두 Compose의 `config --quiet` 통과. internal 망·RO 소스/수집 로그 마운트·자원·로그 회전 확인.
- A+B live 실행 서비스 상한 CPU 1.89개·1472MiB. 일회용 A 도우미 추가 0.07CPU·112MiB도 기본 상한 이내.
- 망 검사 사전·사후 통과, 시험·대조 단말 HTTPS 200 사전 확인. 호스트 방화벽·라우팅·DNS·인증서 변경 없음.
- 각 회차 별도 제한: 동시성1, 요청 간격1초 이상, 최대20요청, 요청당5초, 전체120초.

## 원본·요청 추적 대조

관제 DB의 incident_alerts → alert_events → normalized_events → raw_logs를 SELECT로 대조했다.
각 사건의 ERP 근거는 해당 회차 시간 안의 5건이며 모두 live·trusted, 원본 raw_id5건과 Caddy request_id 정확 연결5건이 존재했다.
세 사건은 서로 다른 근거를 사용했다. 승인3건은 모두 released이며 마지막 GW_BLOCK 규칙은0개다.
전체 실행 출력·종료 코드·원본 ID 목록·마지막 망 검사 출력은 로컬 증거로 보존했다. 원본 로그·덤프·비밀값·개인 파일은 게시하지 않는다.
