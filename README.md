# Mg · ERP 로그인 탐지 개선

**C 담당인 Mg는 ERP 로그인 기록을 더 정확하게 관제 사건으로 만드는 작업을 맡았습니다.** 여러 계정명이나 IP에 흩어진 실패도 찾고, 입력 오류나 중간 로그인 성공 때문에 별개로 봐야 할 실패가 하나의 사건으로 합쳐지는 경우를 줄였습니다.

## 1. 내가 만든 기능

### 여러 계정명이나 IP에 흩어진 실패도 찾아냅니다

세 규칙은 5분 동안 신뢰된 출발지에서 ERP가 인증을 거부한 기록(`401`)을 확인합니다.

| 규칙 | 언제 사건이 생기나요? | 화면에서 할 수 있는 일 |
| --- | --- | --- |
| 기존 · 같은 계정명과 같은 IP | 한 실패 묶음에서 같은 계정명과 IP로 **5회** 실패 | 근거를 보고, 기존 조건을 충족하면 차단을 승인할 수 있습니다. |
| Mg 추가 · 같은 IP에서 여러 계정명 | 한 IP에서 **서로 다른 계정명 3개**로 실패 | 관련 계정명과 원본 로그를 확인합니다. 조사용입니다. |
| Mg 추가 · 같은 계정명에서 여러 IP | 한 계정명으로 **서로 다른 IP 3곳**에서 실패 | 관련 출발지와 원본 로그를 확인합니다. 조사용입니다. |

**예를 들어** 같은 IP에서 `alice → alice → bob` 순으로 실패하면 계정명은 두 개입니다. 5분 안에 `charlie`가 추가되면 세 개가 되어 조사용 사건이 생깁니다. 두 추가 규칙의 사건에는 **조사용 · 차단 불가**가 표시되며 서버에서도 승인을 거부합니다. [탐지 함수와 한글 주석](src/soc/detector.py#L177)

### 서로 다른 실패 묶음으로 생긴 불필요한 사건을 줄입니다

형식 오류(`400`)는 인증 실패에서 뺍니다. 같은 계정·신뢰된 같은 IP·같은 종류의 수집 기록에서 로그인에 성공하면, 기준에 못 미친 실패를 앞뒤로 나눠 셉니다.

| 같은 합성 로그로 비교한 경우 | 변경 전 → 변경 후 |
| --- | ---: |
| 인증 실패 4회 + 입력 형식 오류 1회 | 사건 **1 → 0** |
| 실패 2회 → 로그인 성공 → 실패 3회 | 사건 **1 → 0** |
| 중간 성공 없이 인증 실패 5회 | 사건 **1 → 1** |
| 인증 실패 5회 → 로그인 성공 | 사건 **1 → 1** |

이미 사건이 생겼다면, 마지막 실패 뒤 5분 안에 조건에 맞는 성공의 **시각과 원본 기록 번호**를 상세에서 보여줍니다. 정상 직원도 성공 전에 실제 인증을 5회 연속 실패하면 사건으로 잡힐 수 있습니다. 담당자는 실패와 성공 기록을 함께 보고 판단합니다. [실패를 묶는 코드](src/soc/detector.py#L77) · [성공 기록 조회](src/soc/repository.py#L167)

## 2. 팀원 적용 방법

기능은 이미 팀 `main`에 들어갔습니다. 팀원은 캡스톤 저장소에서 **본인 작업 브랜치**인지 먼저 확인하고, 작업 중인 파일을 보존한 뒤 최신 `main`을 반영하면 됩니다.

```bash
git status --short --branch
git fetch origin
git merge origin/main
python -B -m unittest discover -s tests -v
```

Windows에서 Python을 `py`로 실행한다면 마지막 명령의 `python`을 `py`로 바꿉니다. 병합에서 충돌이 나오면 테스트를 실행하기 전에 겹치는 파일부터 정리합니다. [상세 적용 절차](Mg_LOGIN_DETECTION_GUIDE_codex.md#5-팀원-적용-방법)
## 3. 적용 후 확인할 결과

- [ ] 기존 규칙의 실패 4회에서는 경보가 없고, 5회에서 사건이 생깁니다.
- [ ] 두 추가 규칙은 서로 다른 값이 3개가 되면 사건이 생기고, 같은 기록을 다시 처리해도 사건이 중복되지 않습니다.
- [ ] 조사용 사건에서는 계정명·출발지·원본 로그를 볼 수 있고, 화면과 서버에서 차단 승인이 제한됩니다.
- [ ] 실패 5회 뒤의 성공이 상세에 표시되며, 기존 승인·해제 흐름도 동작합니다.

**확인한 범위** PR #34가 반영된 `main`에서 검증한 PR #35의 로컬 결과는 **40개 통과, PostgreSQL 연동 1개 건너뜀**입니다. 팀 Docker·PostgreSQL 환경에서 실제 화면과 저장 결과를 확인하는 단계가 남아 있습니다. [팀 환경 검증 체크리스트](Mg_LOGIN_DETECTION_GUIDE_codex.md#6-적용-후-검증-체크리스트)
