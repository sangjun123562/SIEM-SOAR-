# 가상 기관 로그인 — 보안관제 시연용

사용자 요청(2026-11-18)으로 구매 신청·승인·반려 업무를 제거했다.
계정 선택 → 정상/실패 인증 → 세션 확인 → 로그아웃만 제공한다.
이 변경은 초기 구매 업무 범위를 줄이는 합의된 범위 변경이다.

## API
- GET /: 기관 통합 로그인 화면
- POST /api/login: 기존 계정·비밀번호 검증과 로그인 감사 기록
- GET /api/session: 현재 인증 정보, 미인증 401
- POST /api/logout: 세션 해제와 로그아웃 기록
- 구매·품목·결재 API는 제거되어 404다.

## 데이터와 증거 보존
ERP PostgreSQL 사용자와 기존 구매 테이블/행은 삭제·초기화하지 않았다.
과거 purchase_* 관제 로그와 원본 raw_id 계약도 그대로 보존한다.
새로운 구매·결재 동작은 제공하거나 기록하지 않는다.

## 화면과 인증
입력형 텍스트 필드 없이 계정을 선택한다. localhost 시연 연결 프로그램이
해당 테스트 계정의 인증값을 메모리에서 공급하며 실제 서버의 비밀번호 검증은 유지한다.
인증값은 저장소 HTML·로그에 넣지 않는다. 직접 Caddy 주소에서는 인증값 공급 없이
계정 선택만으로 로그인되지 않는다. 보안 시연 도구의 실패 유형은 클릭당 1회만 전송한다.
화면 부서 표시는 영업→행정지원과, 개발→디지털정보과이며 DB 코드는 유지한다.

## 로그와 검증
login_success / login_failed / logout 및 request_id, client_ip, peer_ip,
client_ip_trusted 등을 기존 계약대로 기록한다. 비밀번호·쿠키·요청 본문을 기록하지 않는다.
Caddy만 전달 IP를 신뢰하며 미신뢰 경로는 별도로 기록한다.

```bash
cd testbed
bash scripts/verify_day4.sh
```

이 시험은 실제 요청·로그와 N-1/N 탐지 함수를 검증한다.
관제 DB 적재와 사건 화면까지의 완료 여부는 최신 4일 차 점검 문서를 별도로 확인한다.

## 로그인 후 업무 홈
정상 인증 후에는 로그인 화면과 분리된 기관 포털로 전환한다.
업무 홈·내 계정·이용 안내 메뉴와 세션 확인·로그아웃을 제공한다.
계정·소속·역할은 기존 인증 API 응답을 사용한다. 확인 시각은 응답을 받은 브라우저 시각이다.
세션 확인 실패 시 마지막 계정 정보는 남기되 상태를 확인 불가로 표시하고,
401 응답 또는 로그아웃 후에는 로그인 화면으로 돌아가 표시된 계정 정보를 지운다.
구매 업무·가짜 통계·보안 경보를 추가하지 않는다. 관제 앱과 별개의 ERP 접속 후 화면이다.
